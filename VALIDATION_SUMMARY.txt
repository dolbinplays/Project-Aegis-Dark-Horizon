PURPOSE
-------
1. Fix Classic Lineup shots whose authoritative target exists in the resolved tactical frame but is missing from the sequential presentation roster at the moment the tracer is drawn.
2. Shorten long Classic Lineup playback without changing combat simulation, RNG, tactical rules, win probability, or VIP survival authority.

CONFIRMED INVISIBLE-TARGET ROOT CAUSE
-------------------------------------
`tacticalAiSequentialPlaybackFrames(...)` starts each sequential action group from the prior presentation frame's actor roster. A newly revealed/newly encountered alien can already be a valid target in the new authoritative target frame while still being absent from that prior presentation roster. Updating the existing working array with `.map(...)` cannot insert the missing identity, so the shot could carry a valid `toId` while no corresponding alien paper doll was rendered.

REPAIR
------
- Sequential playback now upserts a missing actor from the authoritative target frame before that actor's action is presented.
- An observable AEGIS shot upserts its target before the shot frame and marks that target presentation-visible for that frame.
- Contact-interrupt/replan presentation likewise upserts newly revealed alien identities before displaying the contact.
- Lethal staging remains intact: the target is still present for the shot, then the established impact/death transition commits afterward.
- The repair changes presentation construction only; it does not spawn a second tactical actor or modify resolver authority.

OUTCOME-PRESERVING FAST CLASSIC PACING
--------------------------------------
- Automatic Classic playback can skip redundant quiet per-actor movement/presentation frames and advance to the next consequential frame.
- Every phase-complete frame remains retained, so round state is never skipped from the underlying playback record.
- Observable shots, impacts, contact/replans, reinforcement arrivals, rescue/escort/extraction changes, deaths, Beacon/UFO-bay events, and terminal states remain consequential presentation frames.
- Consequential events receive longer display delays than quiet state transitions.
- Manual `Next` remains exact one-frame stepping. The complete frame array remains available for manual inspection/report timeline use.
- The speed-up is presentation-only. `resolveMission(...)` is byte-for-byte identical to Browser 0810.
